taku-biyori バックエンドの API 仕様。

認証

Better Auth（メール/パスワード・ソーシャルログイン）を利用。認証済みセッションのCookieをリクエストに含めること。 未認証の場合は 401 Unauthorized を返す。

命名規則

  • URLは /sessions を使用
  • コード内の変数・型名は gameSession / GameSession プレフィックスを使用（Better Auth の session と衝突回避のため）

ステータス遷移

卓（ゲームセッション）のステータスを遷移させる。作成者のみ操作可能。

このエンドポイントは DB のファクトカラムを更新し、ステータスはサーバーが再導出して返す。

操作内容：

  • open: is_published = true にセットする。 open_until が設定済みで未来の場合は導出ステータスが open になる。 open_until が null または過去の場合は即座に scheduling になる。
  • completed: completed_at に現在時刻をセットする（today 状態のときのみ有効）。

scheduling → confirmed の遷移は POST .../availability-dates/{dateId}/confirm で行う。 逆方向への遷移は不可。

Authorizations:
sessionCookie
path Parameters
id
required
string <uuid>

卓（ゲームセッション）のID

Request Body schema: application/json
required
status
required
string
Enum: "open" "completed"
  • open: is_published = true にセット（導出ステータスは open_until の値による）
  • completed: completed_at に現在時刻をセット（today 状態のときのみ有効）

Responses

メンバーが候補日に対して回答する。既存の回答があれば上書き。 ステータスが confirmed 以降は回答不可。

認証あり（ログインユーザー）

Cookie のセッション情報からユーザーを解決し、そのユーザーに紐づく メンバーレコードを自動で特定する。memberId は省略可。

認証なし（ゲスト）

memberId は必須。指定した memberId が user_id=null（ゲスト）で あることをサーバー側で検証する。user_id != null のメンバーを指定した 場合は 403 を返す。

path Parameters
id
required
string <uuid>

卓（ゲームセッション）のID

dateId
required
string <uuid>

日程候補のID（availability_dates.id）

Request Body schema: application/json
required
memberId
string <uuid>

ゲストが回答対象メンバーを明示する場合に指定。ログインユーザーは省略可（Cookie から自動解決）

answer
required
string (ScheduleAnswer)
Enum: "ok" "maybe" "ng"
  • ok: 参加可能（◯）
  • maybe: 調整可能（△）
  • ng: 参加不可（×）
comment
string <= 200 characters

Responses

http://localhost:3000/api/game-sessions/{id}/availability-dates/{dateId}/responses

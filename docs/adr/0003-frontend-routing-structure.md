# ADR 0003: フロントエンドのページ・ルーティング構造を定める

## Status

Proposed

## Context

現在のフロントエンドはルート `/` にセッション一覧（`features/Home/`）を置いている。
今後、シナリオ管理機能の追加と、未ログインユーザー向け LP の実装が予定されている。

この状況で、`features/Home/` をそのままダッシュボードとして拡張していくか、
セッション一覧専用のディレクトリ・パスとして位置づけるかを決める必要が生じた。

### 解決したい課題

- `features/Home/` の責務が曖昧なため、将来の機能追加時に「Home に詰め込む」か
  「別ページを作る」かが毎回判断コストになる
- シナリオ管理など新ドメインを追加したとき、どのディレクトリ・パスに置くべきかルールがない
- LP 実装時に `/` の扱いが変わるため、現時点でルーティング全体の方針を固めておきたい

### 検討した選択肢

1. **Home = セッション一覧のまま運用**  
   現状維持。新機能は別パスに独立させる。`/` は常にセッション一覧。
2. **Home = ダッシュボードとして育てる**  
   `features/Home/` にセッション・シナリオ両方のサマリーを追加していく。
3. **LP・ダッシュボード・機能別一覧を分離する（採用案）**  
   `/` を LP、ログイン後は `/dashboard`、各ドメインは独自パスを持つ。

### 各選択肢の評価

| 観点 | 1. Home = 一覧のまま | 2. Home = ダッシュボード化 | 3. 分離（採用案） |
|---|---|---|---|
| 機能追加時の拡張性 | △ 新機能が孤立しがち | △ Home が肥大化しやすい | ✓ 各ドメインに独自パス |
| ルーティングの一貫性 | △ ドメイン境界が曖昧 | ✗ Home の責務が拡散 | ✓ ページの役割が明確 |
| LP 実装時の影響 | ✗ `/` の扱い変更が必要 | ✗ `/` の扱い変更が必要 | ✓ LP は `/` に素直に収まる |
| 実装コスト（現時点） | 低 | 低 | 中（現 Home の移動が必要） |

## Decision

**各ドメインはそれぞれ独立したルートパスを持つ構造を採用し、まず `features/Home/` を
`features/GameSession/List/` に移動してルートを `/game-sessions` とする。**

### 1. 現時点のルーティング構造

| パス | 用途 | 認証 | 機能ディレクトリ |
|---|---|---|---|
| `/` | LP（未ログインユーザー向け） | 不要 | `features/LP/`（実装予定） |
| `/game-sessions` | セッション一覧 | 必要 | `features/GameSession/List/` |
| `/game-sessions/:id` | セッション詳細 | 条件付き | `features/GameSession/Detail/` |

ログイン後は当面 `/game-sessions` へ遷移させる。
複数ドメインが揃った段階で `/dashboard` を設けてログイン後の遷移先を切り替える。

### 2. 現 `features/Home/` の移動

現在の `features/Home/`（セッション一覧）を `features/GameSession/List/` に移動し、
ルートパスを `/` から `/game-sessions` に変更する。

## Consequences

### Positive

- LP を独立して設計できるため、未ログインユーザーへの訴求が可能になる
- 各ドメイン（セッション・シナリオ等）がそれぞれ独立したルートを持ち、
  機能追加時にどこに置くべきかが自明になる
- `features/GameSession/List/` の命名でドメイン所属が明確になる

### Negative

- 現 `features/Home/` の移動と、TopView のルート変更が必要
  - → 影響範囲は `router/index.ts` と `TopView.vue` の参照のみで軽微

### Risks

- 将来 `/dashboard` を設けた際に、各一覧ページとの役割重複が生じる可能性がある
  - → ダッシュボードは「サマリー＋ナビゲーション」に限定し、一覧機能は各ページに委ねるルールを維持する

## 決めていないこと

| 項目 | 決めない理由 | いつ決めるか |
|---|---|---|
| `/dashboard` の導入タイミングと構成 | 複数ドメインが揃うまで必要性が生じない | シナリオ管理など2つ目のドメイン機能の実装開始時 |
| LP のデザイン・構成 | 現フェーズでは未ログインユーザーの流入を想定していない | 公開・マーケティング施策を検討するとき |

taku-biyori バックエンドの API 仕様。

募集枠（lobby）

卓（game_session）が担っていた募集・日程調整の責務を分離した前段の概念。 人を多めに集めて候補日を◯△×で調整し、ホストが「その日に来られるメンバー」を選出して卓を確定する。 ゲストは Guest-Token ヘッダーで参加・日程回答ができる（卓側と同じ仕組み）。 URL は /lobbies、ステータスは draft/open/scheduling/confirmed/cancelled をファクトカラムから導出する。

認証

Better Auth（メール/パスワード・ソーシャルログイン）を利用。認証済みセッションのCookieをリクエストに含めること。 未認証の場合は 401 Unauthorized を返す。

命名規則

  • URL は /game-sessions・/lobbies を使用
  • コード内の変数・型名は gameSession / GameSession プレフィックスを使用（Better Auth の session と衝突回避のため）

ステータス遷移

卓（ゲームセッション）のステータスを遷移させる。作成者のみ操作可能。

このエンドポイントは DB のファクトカラムを更新し、ステータスはサーバーが再導出して返す。

操作内容：

  • open: is_published = true にセットする。 open_until が設定済みで未来の場合は導出ステータスが open になる。 open_until が null または過去の場合は即座に scheduling になる。
  • completed: completed_at に現在時刻をセットする（today 状態のときのみ有効）。
  • cancelled: cancelled_at に現在時刻をセットする（confirmed/today 状態のときのみ有効）。 中止した卓は削除せず「中止」として残す。募集由来の卓でも募集枠は confirmed のまま戻らない。

scheduling → confirmed の遷移は POST .../availability-dates/{dateId}/confirm で行う。 逆方向への遷移は不可。

Authorizations:
sessionCookie
path Parameters
id
required
string <uuid>

卓（ゲームセッション）のID

Request Body schema: application/json
required
status
required
string
Enum: "open" "completed" "cancelled"
  • open: is_published = true にセット（導出ステータスは open_until の値による）
  • completed: completed_at に現在時刻をセット（today 状態のときのみ有効）
  • cancelled: cancelled_at に現在時刻をセット（confirmed/today 状態のときのみ有効）

ゲストリンク経由でメンバー参加（完全匿名）

ゲスト招待リンク経由でセッションにメンバーとして参加する。認証不要。 user_id は null として登録され、guest_name に入力した名前を使用する。

  • Guest-Token ヘッダー必須。卓の guest_link_token と一致しなければ 403。
  • 参加できるのは status === open のときのみ（通常参加と同条件）。それ以外は 422。
  • 重複参加を許容する（本人確認手段がないため。同名でも別レコードになる）。
  • 満員（maxMembers）チェックは行わない（通常参加にも無いため揃える）。

  • Guest-Token ヘッダー必須。募集枠の guest_link_token と一致しなければ 403。
